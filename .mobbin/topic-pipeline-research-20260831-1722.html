Pipeline 应选择 Topic，而不是 Data Source

研究连接器、数据同步、知识集合与工作流之间的产品边界。核心结论：Data Source 是同步机制，Topic 是稳定的业务输入。

Connector建立外部连接
Select assets选择需要同步的内容
Background sync持续同步与健康检查
Topic形成稳定的内容边界
Pipeline选择 Topic 并处理

这个流程叫什么？

Knowledge ingestion & collection scoping，中文可称“知识接入与主题归集”。它不是单纯的数据源设置，也不是 Pipeline 编辑，而是连接二者的领域流程。

三条设计原则

1连接器负责接入和同步状态。
2Topic 负责内容范围和业务语义。
3Pipeline 只引用稳定的 Topic。
最接近 Hover

Sana AI：Integration 与 Collection 分层

连接器是后台同步器；Collection 是用户实际使用、共享和组织知识的边界。这是最接近 Topic 模型的参考。

相邻模式

Wix：导入方式不是下游依赖

CSV 只是创建 Collection 的一种方式。创建完成后，页面和 Dataset 都连接到 Collection，而不是继续引用原始文件。

有用的反例

n8n：Workflow 直接选择 Data Source

通用自动化产品把 Datastore 当作画布节点。这种方式灵活，但会让 Pipeline 与技术数据源强耦合。

建议的 Hover 方案

Pipeline 创建器直接选择 Topic。Connector 图标、同步状态与最近同步时间作为 Topic 的上下文信息展示，但不成为主选择对象。

Configure processing

设置处理规则，Pipeline 不需要知道 Topic 后面有哪些连接器。
